## 整室审批如何影响个人预约

学生提交教室申请后，一级审批通过，教室内的座位仍可预约。二级审批时，M2 释放本地事务，通过 HTTP 向独立运行的 D 资源服务发送 `PUT /internal/v1/classroom-holds/{申请单号}`。D 重新检查审批权限、截止时间、开放时段和占用冲突，在同一事务中保存终审结果、房间占用、通知和审计。M1 查询房间内任一座位时，都能返回 M2 来源和同一个申请单号。

服务不可达时申请保持待审。如果服务已经提交但回复丢失，同一审批人使用相同备注重试可取回原结果，数据库只保留一条占用。取消获批申请时，系统按原单号释放房间。[网络接口与模块边界](architecture.md)

## 修复与行为变化

| 范围 | 原问题或课程要求 | 本地验收结果 |
| --- | --- | --- |
| M1 并发预约 | SQLite 上两个请求可同时通过冲突检查 | 两名学生抢同一座位的重叠时段，仅一人成功。相同幂等键并发重试返回同一单号。 |
| M1 查座与开放时间 | 闭馆时查座显示可用，提交才失败；既有房间难以调整时段 | 管理员可在网页修改开放时间，系统保留修改审计。新查询、预约及待终审申请遵守新时段，已确认安排保留。 |
| M1 历史原座复约 | 历史按钮只回填时间，跨月记录可能落在过去 | Chrome 从两个月前的记录定位原座，在有效日期完成复约。首次进入座位页会加载预约历史。 |
| M1 提醒与违约 | 需区分按时签到和未签到，并防止轮询重复投递 | 本机 SMTP 收件箱验证开始前 15 分钟提醒、开始后 10 分钟催签到、开始后 15 分钟释放通知。按时签到不触发后两封；逾期取消不能绕过违约。 |
| M2 教室审批 | PostgreSQL 审批时报 500，超时后仍可能通过 | 两级审批、驳回、超时、占用冲突、网络中断及重试均有行为测试。一级通过不占座，终审成功锁全室。 |
| M3 物业工单 | PostgreSQL 上报修返回 500 但工单已入库；课程要求验证整室下架 | 创建成功仅留一单。整室开工后全部座位显示工单号，报完工仍不可订，验收只解除该维修占用。有原预约的座位仍显示原预约。 |
| D 与 Agent 权限 | 预览后被撤权的用户仍能确认写入 | 直接接口与 Agent 确认共用写入权限检查。撤权后无法通过旧预览订座、申请教室、报修或取消个人预约。 |

在仓库根目录执行以下 PowerShell 命令可验证 SQLite。PostgreSQL 复跑时，在同一终端将 `TEST_POSTGRES_URL` 设置为专用测试库的 SQLAlchemy 连接串，再执行同一条 pytest 命令。测试账号需有创建 schema 的权限。

```powershell
uv sync --frozen
uv run playwright install chromium
$env:RUN_BROWSER_TESTS = "1"
Remove-Item Env:TEST_POSTGRES_URL -ErrorAction SilentlyContinue
uv run pytest -q
```
